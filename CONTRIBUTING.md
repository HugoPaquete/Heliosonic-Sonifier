# Contributing to Heliosonic Sonifier

Thank you for your interest in the Heliosonic Sonifier.

> [!IMPORTANT]
> This repository is **documentation-only**. The source code and compiled
> executables are proprietary and are **not distributed**. Contributions are
> therefore limited to documentation, media, and related non-code assets.

## What you can contribute

| Area | Examples |
|------|----------|
| **Documentation** | Corrections, clarifications, expanded explanations in `docs/` |
| **Translations** | Translating docs into other languages (e.g. `docs/pt/`) |
| **Diagrams** | Improved Mermaid or exported architecture diagrams |
| **Media** | Screenshots, hardware photos, demo-video thumbnails for `assets/` |
| **Preset descriptions** | Written descriptions of musical presets and use-cases |
| **Typos & links** | Fixing broken links, formatting, and spelling |

## What you cannot contribute

- ❌ Source code or patches to the proprietary engine
- ❌ Compiled executables or binaries
- ❌ Reverse-engineered implementations
- ❌ Material that rebrands the project without permission

## How to contribute

1. **Open an issue** for bugs, broken links, or unclear documentation.
   Use a clear title and reference the specific doc file and section.
2. **Fork the repository**, create a branch, and open a **Pull Request** for
   substantive changes.
   - Branch naming: `docs/<short-description>` or `media/<short-description>`
   - Keep the academic/artistic tone consistent with existing docs.
3. **Keep changes focused.** One topic per PR makes review faster.

## Documentation style guide

- Use GitHub-Flavored Markdown.
- Use `> [!NOTE]`, `> [!IMPORTANT]`, and `> [!WARNING]` callouts where helpful.
- Keep tables aligned and code blocks language-tagged.
- When referencing physical models, preserve the **VERIFIED / THEORETICAL /
  ARTISTIC** distinction (see `docs/08-SCIENTIFIC-TRANSPARENCY.md`).
- Do not introduce claims that the system is a scientific simulation.

## Media guidelines

- Screenshots: PNG, named descriptively (e.g. `01-main-interface.png`).
- Hardware photos: JPG, well-lit, placed in `assets/hardware/`.
- Provide `alt` text for every image reference.

## Reporting issues

Open an issue describing:
- The doc file and section affected
- What is incorrect or unclear
- A suggested correction, if you have one
